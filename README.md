# DONKI-REJI ── 無人レジ（セルフレジ）おしはらい練習アプリ

ドン・キホーテ／MEGAドン・キホーテ（アピタ・ユニー系店舗を含む）の
**フルセルフレジ**の操作の流れを再現し、子どもが「自分で商品をスキャンして、自分でお金を払う」
一連の操作を安全に練習できるようにしたWebアプリ。

HTML + CSS + 素のJavaScript のみ。ビルド不要・外部通信なし・インストール不要。

> ⚠️ 本アプリは**学習用の非公式アプリ**です。株式会社ドン・キホーテおよびmajicaとは関係ありません。
> 実機の画面デザインやロゴは再現していません（文言と操作手順だけを参考にしています）。

## つかいかた

`index.html` をブラウザで開くだけ。

```bash
xdg-open index.html
```

タブレット・電子黒板でも使えるよう、ボタンは最小64px・文字は大きめにしてあります。

### 画面サイズへの合わせ方（iPad縦を基準にしてあります）

実機のモニタは**4:3の横長**です。これを無視して端末の画面いっぱいに広げると、
iPad縦のような縦長の画面では上下に間延びして実機と似ても似つかなくなります。そこで:

- **タブレット以上（幅600px以上）** — 画面を**4:3に固定**し、上下中央に置く。
  モニタの下には、実機でバーコードをかざす位置・お金を入れる位置にあたる
  「スキャナ／紙幣投入口／硬貨投入口」を置いて、余った縦のスペースをレジ台として使う
- **縦の余裕が足りないとき（iPad横向きなど）** — 4:3を保ったまま**モニタごと縮小**する
- **中身が4:3に収まらない画面**（商品棚のあるスキャン画面など）だけ、必要な分だけ縦に伸ばす。
  それでも収まらなければ本文の中だけがスクロールする
- **操作ボタンの帯は本文の外**に出してあるので、本文がスクロールしても
  「お会計」「支払う」は常に見える位置にある
- **スマホ縦（幅600px未満）** — 4:3にすると画面が小さくなりすぎるため固定せず、縦に広く使う

実測で確認した表示サイズ:

| 端末・向き | 画面の表示サイズ | 比率 | ページのスクロール |
|---|---|---|---|
| iPad 縦 768×1024 | 716×537 | 4:3 | なし |
| iPad Air 縦 820×1180 | 768×576 | 4:3 | なし |
| iPad Pro 縦 1024×1366 | 968×726 | 4:3 | なし |
| iPad 横 1024×768 | 797×598 | 4:3 | なし |
| スマホ縦 375×812 | 347×631 | — | なし |

## 画面の流れ

```
はじめる
 → レジ袋の選択（有料レジ袋 S/L ／ マイバッグ ／ 袋不要）
 → majicaをお持ちですか？（はい → バーコードをスキャン → 残高確認）
 → 商品をスキャン（バーコードなし商品は左のボタンから）
 → お会計 → お支払いへ
 → 支払方法（マジカ払/チャージ ／ ポイント払 ／ 現金 ／ クレジットカード）
 → 支払い（現金は紙幣・硬貨を1枚ずつ投入）
 → おつり・レシート
```

実機の操作手順の調査結果と出典は [docs/セルフレジ調査.md](docs/セルフレジ調査.md) にまとめてあります。

画面のデザイン（水色／ピンクの背景、オレンジと赤のタイル、上部のメッセージバーと緑の罫線、
会計機No、店員呼出・English・majica残の下部バー）は、**実機の写真に合わせて作ってあります**。

## 再現している実機の仕様

- トップ画面でレジ袋を先に選ぶ（majica確認はその次）／チャージ・残高照会のボタンも同じ位置にある
- **支払方法は4つだけ**（マジカ払/チャージ・ポイント払・現金・クレジットカード）。写真の端末に電子マネー・商品券のタイルは無い
- 全画面に「店員呼出」、支払方法画面には「English」と「会計機No」
- majicaカードは**レジ左横のハンディスキャナ**で読み取る
- バーコードのない商品は「やさい」「くだもの」「おさかな」「その他」から選ぶ
- レジ袋はスキャン中でも追加できる
- **硬貨は一度に20枚まで**（超えると警告が出る）
- **majicaマネーと現金の併用は不可**。残高不足なら「チャージ」か「別の支払い方法」
- **ポイントは1ポイント＝1円**、1円単位で使える。足りない分は他の方法で払う
- クレジットカードは**1回払いのみ**

## カメラでQRを読み取る

スキャン画面の「📷 カメラでスキャン」で、実際にカメラを使って商品を登録できます。
majicaカードも同じ方法で読み取れます。

**QRの中身は商品のバーコード番号そのもの**にしてあります。こうしておくと、
印刷したQRカードでも本物のJANバーコードでも、同じ照合処理で商品が引けます。

### 印刷用のQRカード

[cards.html](cards.html) を開いてそのまま印刷し、点線で切り分けて使います。
**空き箱や実物に貼ると、より本物に近い練習になります。**
13枚（majicaカード1枚＋商品12枚）。アプリ右上の「🖨 QRカード」からも開けます。

商品を増やしたら `js/data.js` を直してから、カードを作り直してください。

```bash
node tools/make-cards.js
```

### 端末ごとの読み取り方法

| 端末 | 読み取りに使うもの | 本物のJANバーコード |
|---|---|---|
| iPad / iPhone（Safari） | 同梱の [jsQR](vendor/) | ✗ QRのみ |
| Android Chrome など | ブラウザ標準の `BarcodeDetector` | ✓ 読める |

iOS/iPadOS の Safari には `BarcodeDetector` が無いため、QRの読み取りライブラリを
リポジトリに同梱しています（CDNから読むと学校のネットワークで遮断されることがあるため）。
標準APIが使える端末ではそちらを優先し、本物のJANバーコードも読みます。

### 注意

- **カメラは https でないと使えません。** 公開URL（GitHub Pages）なら問題ありませんが、
  ファイルを直接開く `file://` や、`http://` の自前サーバーでは動きません
- カメラが使えない・許可されない場合でも、**従来どおり画面の商品をタップして登録できます**。
  カメラは追加の手段であって、必須ではありません
- 同じQRを連続で読んでも、**2秒以内は二重登録されません**

## 練習向けの機能

| 機能 | 内容 |
|---|---|
| ひらがなモード | 画面の文言をすべて**ひらがな・わかちがき**に切り替える（右上のボタン） |
| 音のON/OFF | スキャン音・投入音を消せる（聴覚の過敏さへの配慮） |
| おつりの内訳表示 | おつりを金種ごとに分けて表示する |
| レシート表示 | 明細・支払い方法・おつりを確認できる |
| やりなおし | いつでも最初から／majica残高は引き継ぐ |
| カメラ読み取り | 印刷したQRカードを実際にカメラで読める（上記参照） |

## 構成

```
index.html        画面の骨組み
css/style.css     見た目（タッチ操作前提の大きめUI）
js/data.js        商品データ・金種・画面文言（漢字／ひらがなの対訳）
js/app.js         状態管理と画面遷移
cards.html        印刷用のQRカード（tools/make-cards.js で生成）
vendor/           同梱した外部ライブラリ（QR読み取り用の jsQR）
tools/            QRカードの生成スクリプト
docs/セルフレジ調査.md   実機の操作手順の調査結果と出典
```

商品を増やすときは `js/data.js` の `PRODUCTS` に1行足すだけ。
`k:` が漢字表記、`h:` がひらがな表記です。
